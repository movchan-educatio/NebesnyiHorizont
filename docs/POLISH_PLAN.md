# План доведення гри до ідеалу

**Проєкт:** Nebesnyi Horizont — Godot 4 FPV-симулятор
**Фокус:** мобільна версія (iPhone / iPad) без втрати ПК-функціоналу
**Дата:** 2026-11-19
**Поточний етап:** карта «Аеропорт» інтегрована з повним функціоналом `BigLevel` (коміт `c88cdb6`, IPA `ios-build-83`)

---

## 0. Принципи

1. **Не ламаємо працююче.** Будь-яка зміна ядра (`BigLevel.gd`, `frontline_terrain.gd`,
   `Level.gd`, autoload) — окрема гілка, бекап, повний QA-прогон усіх карт.
2. **Вимірюй, не здогадуйся.** Кожен етап має метрику до/після (FPS, draw calls,
   час старту, latency, crash-free).
3. **Мобільний перший.** Усе, що додається, перевіряється в профілі `mobile` /
   `MOBILE_UI=1` і на реальному пристрої перед релізом.
4. **Адитивність.** Нові карти/режими додаються новими файлами й рядками, без
   переписування існуючих механік.
5. **Один канал істини.** Усі назви карт, підказки й локалізація — у словниках
   (`MainMenu`, `MobileMenu`, `MenuUI`), а не в розкиданих рядках.

---

## 1. Базова оцінка (що вже добре)

| Сфера | Стан |
|---|---|
| Архітектура карт | `BigLevel` + тонкі обгортки; процедурний `frontline_terrain`, MultiMesh-батчинг |
| Якість/продуктивність | `QualityManager` (LOW/MED/HIGH), `PerformanceGovernor` (ціль ~58 FPS) |
| Візуал | HDR-небо, ACES, SSAO/SSIL/volumetric на ПК; мобільний профіль їх вимикає |
| Контент | 5 фронтових карт + місто + аеропорт, місії, льотна школа, РЕБ, БЧ/скид |
| Керування | TouchControls + MobileInput + ELRS Wi-Fi, емуляція джойстика |
| CI/CD | GitHub Actions `ios.yml` → IPA у реліз (непідписаний) |
| QA аеропорту | 48/48 режимів/місій, 9 колізій, 212 draw calls, ~674k primitive, 60 FPS |

**Відомі слабкі місця:** нерівномірна якість текстур/матеріалів між картами; відсутній
автоматичний регресійний прогон; фрагментарна локалізація підказок; немає вимірювання
input-latency на пристрої; IPA непідписаний; немає телеметрії збоїв.

## 2. Етапи шліфування

### P0 — Стабільність і процес (високий пріоритет, 1–2 тижні)

**Мета:** зробити так, щоб будь-яка зміна не ламала інші карти.

- [ ] Створити `test/qa_full_matrix.gd`: один прогон на всі сценарії
      `карта × режим × місія ×special × пресет дрона` з перевіркою:
      наявність `Drone`, `CombatSystem`, `CombatHUD`, `Respawn`, 9+ колізій,
      відсутність `SCRIPT ERROR` у логах.
- [ ] Додати headless-перевірку в GitHub Actions як обов'язковий check перед iOS-збіркою.
- [ ] Запровадити `qa_shots/` еталони скриншотів (вже є для аеропорту — поширити на всі карти).
- [ ] Перевірити всі `.import`/LFS-ассети на консистентність ((GLB-текстури, HDR, PNG).
- [ ] Очистити застарілі `.bak-*` і тимчасові зонди з репозиторію.
- [ ] Запровадити версіювання `CHANGELOG.md` і теги релізів.

**Критерій прийняття:** 100% проходження матриці; 0 `SCRIPT ERROR`; збірка блокується при падінні QA.

---

### P1 — Візуальна цілісність (2–3 тижні)

**Мета:** усі карти виглядають як одна гра.

- [ ] Єдиний колор-грейд: винести налаштування туману/експозиції/ambient у
      `map_grade.gd` і застосовувати до всіх карт (зараз грейд розкиданий по
      `BigLevel._tune_map_environment` та окремихLevel-скриптах).
- [ ] Уніфікувати небо: один HDRI + один ProceduralSky fallback, однаковий
      `sky_rotation` відносно сонця на всіх картах.
- [ ] Матеріали GLB-карт (`city`, `airport`) прогнати через `material_upgrader`
      з маскою «не ховати меші» (для аеропорту вже зроблено — узагальнити).
- [ ] Детальні текстури: normal/roughness для бетону, іржі, асфальту; тайлінг без
      видимих швів; перевірити на мобільному ASTC.
- [ ] Покращити обрій: далекі хребти/міські силуети, height-фог, повітряна перспектива
      (підхід уже реалізований на аеропорті — перенести на інші карти).
- [ ] Додати декоративні шари: пил у променях сонця (уже є), сліди шин, розмітку,
      пошкодження, сезонні варіації (сухий/мокрий ґрунт).
- [ ] Перевірити тіні: один напрямлений光源 + fill; уникнути подвійних тіней від
      DEC-мешів (для фону вже вимкнено).

**Критерій:** візуальний diff між картами — лише біом, не «різні ігри»; 0 видимих швів текстур; стабільний hdr/tonemap.

---

### P2 — Відчуття польоту та керування (2 тижні)

**Мета:** дрон слухається миттєво, особливо на телефоні.

- [ ] Виміряти input-to-photon latency на iPhone (камера з тач-подією → кадр).
      Ціль < 50 мс (ANDROID/iOS low-latency path).
- [ ] Налаштувати криві стіків (expo/deadzone) окремо для touch/ELRS/геймпада;
      зберегти профілі в `Controls`/`MobileInput`.
- [ ] Додати/відполірувати режими допомоги: Angle-assist, altitude hold,
      emergency-stop; перевірити, що ARM/дисарм не подвоюються (уже виправлено для аеропорту).
- [ ] Ергономіка тач-панелі: розмір/позиція стіків, кнопок БЧ/СКИД/RESET/ARM,
      плаваючий стік, HAPTIC-відгук; протестувати на різних розмірах екрана (iPhone SE … iPad Pro).
- [ ] Камера: FOV/tilt per drone (FPV-110°), плавний returned-to-center, захист від
      кліпу prop-лопатей (уже є в `_configure_model_for_camera`).
- [ ] HUD: читаємість на сонці (контраст/outline), масштабування під safe-area/IPhone notch.

**Критерій:** latency < 50 мс, 0 випадків «стіки не реагують», ARM завжди знімає freeze.

---

### P3 — Контент і фрістайл (2–3 тижні)

**Мета:** кожна карта має щільний, різноманітний простір для трюків.

- [ ] Фрістайл-інфраструктура на всіх картах: кільця, арки, тунелі, рампи,
      контейнерні каньйони, слаломи ( провести підхід аеропорту на steppe/village/industrial).
- [ ] Пріоритет видимості: яскраві кільця/мітки, контрастні майданчики під воротами.
- [ ] Місії: додати нові типи (перегони/тайм-тріал, доставка з перешкодами,
      нічний пошук) поверх наявних TAC-01..04 і SPECIAL 01..10.
- [ ] Динаміка: рухомі цілі, конвой, погода/день-ніч, руйнування (уже частково є).
- [ ] Аеропорт: зберегти 11 210 об'єктів, додати ще «видовищні» зони вздовж смуги
      (плановані ангари-каньйони, дахова гонка, паливний слалом).
- [ ] Реplay/kill-cam: зробити стабільним і доступним у всіх режимах.

**Критерій:** ≥ 10 трюкових споруд у зоні видимості зі спавну; кожна місія має унікальний об'єктив.

---

### P4 — Продуктивність (безперервно)

**Мета:** стабільні 58–60 FPS на реальних iPhone/iPad без перегріву.

- [ ] Профілювати на реальних пристроях (iPhone 12/15, iPad Air/Mini) у
      Xcode Instruments / Godot profiler: GPU vs CPU, thermal throttling.
- [ ] Бюджети: draw calls < 250, primitives < 1.2M, VRAM < 500 МБ,
      час завантаження карти < 8 с, 1% low FPS ≥ 45.
- [ ] LOD/дальність видимості для MultiMesh-рослинності й дрібних пропсів
      (уже є `LOD_END`, розширити на нові об'єкти).
- [ ] Текстури: ASTC на iOS, atlas для дрібних пропсів, скоротити кількість
      унікальних матеріалів (зараз ~24 меші/матеріали на аеропорті).
- [ ] Adaptive resolution: `PerformanceGovernor` — додати гістерезис, щоб не
      «хитався» scale3d (на аеропорті він уже тримає 0.70/0.61).
- [ ] Вимкнути тіні для далекого фону й дрібних DEC-мешів (застосовано — узагальнити).

**Критерій:** цільові пристрої тримають метрики 30 хв без тротлінгу.

---

### P5 — UX, онбординг, локалізація (2 тижні)

      виправлено F → «кнопка БЧ на екрані»).
- [ ] Однакові картки карт: прев'ю 1920×1080, назва/тег/складність в обох мовах.
- [ ] Туторіал: 6 модулів льотної школи з адаптацією під тач (уже є в `flight_school.gd`),
      додати «швидкий старт» для фрістайлу без бойових місій.
- [ ] Меню: зменшити кількість кліків до вильоту; запам'ятовувати останню карту/дрон.
- [ ] Доступність: кольори/контраст, розмір шрифтів, налаштування чутливості.
- [ ] Підказки в грі: контекстні (перший ARM, перший БЧ, перший респавн).

## 3. Пріоритетна черга (найближчі 3 дії)

1. **P0:** автоматична QA-матриця в CI + захист від регресій (найбільший ризик зараз).
2. **P4:** вимірювання на реальному iPhone + стабілізація FPS/thermal.
3. **P1:** уніфікація колор-грейду й матеріалів, щоб аеропорт не вибивався з інших карт.
