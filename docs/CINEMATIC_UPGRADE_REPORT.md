## 1. Що спостерігалось «до»

Baseline-скріни збережено в `%TEMP%\opencode\destruction_before\`.

- Сіре пласке небо (процедурний градієнт), різкий горизонт без повітряної перспективи.
- Ударна хвиля — велика напівпрозора «бульбашка» (Fresnel-сфера), яка перекривала сцену.
- Полум'я — одна суцільна помаранчева колона з жорсткими краями квадра (flipbook мав залишкову альфу на межахатласу).
- Ґрунт — однотонна сіро-бежева плита без фактури; контактні тіні відсутні.
- Фінальний грейд — лише чорні смуги + слабка віньєтка.

## 2. Що змінено

### 2.1. `shaders/cinematic_overlay.gdshader` — новий фінальний грейд

Один повноекранний quad, **один семпл `hint_screen_texture`**, усе інше — ALU:

| Етап | Що дає |
|---|---|
| S-curve контраст навколо middle grey | «плівковий» вигляд без вимивання тіней |
| Насиченість + теплий highlight / холодний shadow split-tone | кінематографічна кольорокорекція |
| Halation на гарячих пікселях | м'яке світіння без додаткового texture fetch |
| Органічна еліптична віньєтка | глибина кадру |
| Теплий light leak із кута | сонце в об'єктив |
| Тонке анімоване зерно + опційний сканувальний шум | маскування бандингу запеченого неба |
| Опційний anamorphic letterbox із тонкою теплою лінією | прев'ю/replay, у грі вимкнено |

Вартість на Mobile: **0 додаткових render target, 0 додаткових проходів**, ті самі 1 texture fetch, що й у попередній версії шейдера (який уже працював на iOS у HUD і MobileMenu).

### 2.2. `scripts/util/cinematic_overlay.gd`

- `is_active()` тепер істинний на **всіх реальних платформах** (раніше — тільки mobile), headless виключено для детермінізму QA.
- Додано `attach_canvas()` для CanvasLayer (галерея/replay), збережено сумісний `attach()` для Control.
- Нові параметри грейду (леак, контраст, насиченість, halation, letterbox) передаються в матеріал.

`HUD.gd`, `MobileMenu.gd` — оновлені значення грейду (без зміни логіки шарів: прямоугольник залишається дитиною index 0, HUD малюється поверх і лишається різким).

| Зміна | Ефект | Бюджет |

| Новий `ShockFlashRing`: м'який additive puff-квад, 0.22 с, alpha 0.20 | яскравий ведучий край ударної хвилі | **+1 короткоживущий draw** |

| **`flame_atlas()` переписано**: 6 окремих язиків замість 12 злитих блобів, 64px/кадр, пераftering усіх чотирьох країв | живе полум'я без «обрізаного квадрата» | та самі 512×64 RGBA (~128 КБ) |

| **Авіація**: `CrashFire` масштабується реальним AABB (`fs = extent/12`), квад піднято на `0.55 × висота` | полум'я в корпусі, Apache палає значно більше за Shahed | 0 (той самий квад) |
| **Масштабування**: новий `_unit_extent()` обчислює реальний AABB цілі; `scale_f` вибуху й розмір вогню залежать від розміру техніки (SHAHED ≠ Apache ≠ танк ≠ піхота) | велика техніка палає великим вогнем, маленька — маленьким | 0 (один прохід по візуалах на spawn) |
| **Піхота в галереї**: процедурна фігура, що лежить на землі, + `move_unit=false`; якір вогню прив'язаний до землі (`ground_y`) | тіло не провалюється, полум'я на тілі | −1 GLB у прев'ю |

Усе кешується在 `clear_caches()`. Жодного RigidBody, raycastу на кадр чи нової великої текстури.

### 2.4. `test/destruction_gallery.gd` — еталон вигляду (не частина гри)

- Замість procedurally sky — **запечена золота панорама** `sky_mountains_golden.png` із `PROCESS_MODE_INCREMENTAL` (без stall на першому кадрі).
- Триточкове світло: теплий ключ 1.82 + холодний fill 0.38 + гарячий back-rim 0.70 + теплий ground-bounce 0.18.
- ACES + glow 0.72 + adjustment, fog із aerial perspective, sky ambient/reflection.
- Процедурна фактурна земля (128×128, 3 октави, кешована) і **велика площина 1600 м**, щоб край не вибивався на горизонті.
- 90 частинок пилу в променях (1 GPUParticles, 1 кешована 32px текстура).
- Новий грейд із letterbox, light leak і зерном; титр/фази на окремому шарі 21 (залишаються різкими).
- Камера: повільний push-in і лёгкий roll на детонації, затухаюче тремтіння.

## 3. Чому FPS на iPhone не просідає

1. **Усе дороге запечено або кешовано один раз**: панорама, ґрунтова текстура, flipbook, dust-ring —.genеруються/завантажуються один раз.
2. **Постобробка — один quad і один texture fetch**. На Mobile race renderer це вже існуюча витрата (раніше грейд був у HUD тільки на iOS); додано лише ALU.
3. **Кільця й хвиля стали дешевшими**, ніж були: менша прозора сфера = менше fill-rate, найважливішого мобільного ресурсу.
4. **Полум'я**: той самий 1 draw на об'єкт, +1 короткий flash-quad на вибух. `MAX_ACTIVE_BURNS = 10` не змінено.
5. **HUD і OSD неgradesуються** — вони малюються після грейду, тому залишаються різкими без MSAA.

## 5. Що залишити на наступний етап

1. Прогнати **реальний iPhone** у Xcode Instruments / Metal System Trace (draw calls, GPU frame time, thermals) — без цього будь-які подальші графічні зміни залишаються вгадуванням.
2. Підключити галерею як «режим перегляду руйнувань» у меню.
3. Запечені уламки реальної техніки (Blender Cell Fracture → VAT) замість октаедричних шматів.
