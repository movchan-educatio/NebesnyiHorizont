# Звіт: кінематографічні руйнування, земля, вибухи й вогонь (iOS / FPV-симулятор)

Дата: 2026-11-18
Проєкт: `GodotDrone_LOWSPEC` → GitHub `movchan-educatio/NebesnyiHorizont`
Цільова платформа: iOS (Mobile renderer у Godot 4.6.1; CI збирає 4.7.2)

---

## 1. Що вже було в проєкті (аналіз вихідного стану)

Система руйнувань існувала й була досить розвиненою:

- `combat/destruction_fx.gd` — універсальний шар презентації: багатофазний вибух, удар, горіння, падіння авіації, уламки.
- `combat/explosion.gd` — радіус ураження, ланцюгові реакції, відштовхування дрона, воронка-декаль, димові/вогняні колони.
- `combat/hit_fx.gd`, `combat/tracer.gd`, `combat/sfx.gd` — попадання, трасери, синтезований звук.
- `test/destruction_gallery.tscn` + `destruction_gallery.gd` — окрема галерея-прев'ю на реальних GLB-моделях (танк, БМП, БТР, «Тигр», SAM, Apache, Shahed-136, піхота), яка сама знімає поетапні скріни в `qa_shots/audit/`.
- Асети BinbunVFX (шейдери вибуху) лежать у `Assets/BinbunVFX_Vol2/`, але в галереї їх замінено власною процедурною презентацією.
- Бюджет уже був discipline-oriented: MultiMesh для уламків (1 draw call замість десятків RigidBody), GPUParticles, кешовані процедурні текстури 64×64, обмеження `MAX_ACTIVE_BURNS = 10` і зменшення кількості ефектів на LOW-рівні якості.

**Живий шлях підтверджено:** `combat/vehicle.gd` викликає `DestructionFxScript.destroy(...)` при знищенні й `DestructionFxScript.impact(...)` при падінні авіації. Тобто зміни в `destruction_fx.gd` впливають не лише на галерею, а й на гру.

### Візуальні проблеми «до»

Знімки `qa_shots/audit/destruction_grid_03_blast.png` / `_04_burning.png` (versions до змін) показували:

1. **«Мильні кулі»** — хвиля тиску (`ShockwaveDome`) була великою прозорою сферою радіусом до ~14.5 м, яка перекривала всю сцену і виглядала як бульбашка, а не ударна хвиля.
2. **Плоскі помаранчеві ядра** — `FireballCore` був однотонною sphere з жорстким краєм і занадто великим радіусом; на піку виглядав як світла куля, а не вогняна хмара.
3. **Переекспозиція** — Filmic tonemap + високий ambient змивали контраст; уламки й силуети техніки губились.
4. **Підлога без контакту** — техніка «висіла» на сірих плитах, немає контактних тіней і слідів горіння.
5. **Немає кінематографічної мови** — відсутні letterbox, зерно, віньєтка, повільний момент, тремтіння камери.

## 2. Що змінено

### 2.1. `combat/destruction_fx.gd` (впливає на гру + галерею)

| Зміна | Ефект | Вартість |
|---|---|---|
| Нова кешована 64×64 текстура `create_dust_ring_texture()` — шумне кільце замість залитої радиальної плями на `GroundShockRing` | Ґрунтова хвиля читається як піднятий пил, а не «млинець» | 1 текстура 64×64, 1 альфа-квад |
| `ShockwaveDome`: радіус 14.5 → 8.0, стиснення Y до 0.26, інтенсивність 1.2 → 0.6, час 0.35 → 0.28 с | Прибрано «бульбашку»; залишився плоский швидкий лінзоподібний фронт тиску | **Менше** overdraw, ніж було |
| `FireballCore`: радіус 5.4 → 4.0, м'яка текстура `cloud_puff`, плавний перехід у дим | М'який luminant-вибух замість жорсткої кулі | ті самі draw calls |
| Новий `HotCore` — маленький біло-гарячий спалах, живе 0.30 с | Миттєва детонація читається навіть у slow-mo | +1 короткоживущий additive sphere |
| `Embers` — висхідні іскри на вибуху (10 LOW / 18 HIGH) | Живий вогонь замість статичного спалаху | +1 GPUParticles draw, спільна кешована текстура `spark` |
| `WreckEmbers` у `burn()` (6 LOW / 12 HIGH) | Постійне мерехтіння багаття на уламках | +1 GPUParticles draw на палаючий об'єкт |
| `WreckFire`: 56 → 38 частинок, повільніше й ближче до корпусу | полум'я зливається у випадкову хмару, а не «вежу» однакових спрайтів | **Менше** overdraw |
| Уламки: `BoxMesh` → кешований октаедричний `ArrayMesh` (8 трикутних граней) + випадкове неоднорідне масштабування кожного інстанса | жоден ракурс не дає квадратного силуету; шматки схожі на уламки металу/бетону | той самий 1 draw MultiMesh, 8 трикутників |
| Полум'я: статичний конус → **8-кадровий flipbook** (`flame_atlas()`), generated once as 384×48 texture, що циклічно відтворюється шейдером | органічні язики полум'я, що коливаються, а не палаючі трикутники чи смуги шуму | 1 texture sample на піксель; ~72 KB VRAM |
| Billboard реалізований просто у `vertex()` шейдера (`MODELVIEW_MATRIX`) | працює і на частинках, і на окремому кваді без StandardMaterial3D | 0 |
| Горіння уламків: 38 частинок → **один** flipbook-пламінь-квад на об'єкт + іскри | суцільний живий вогонь замість «вежі» однакових спрайтів | **−37 GPU-частинок на об'єкт** |
| `CrashTrail`: 30 полум'яних частинок → один пламінь-квад, що супроводжує падіння; прибрано подвійний `burn()` для авіації | зникла «колона квадратиків» і полум'я, що залишалось у небі | **−30 GPU-частинок на падаючу ціль** |
| Усі нові ресурси кешуються й очищуються в `clear_caches()` | Немає витоків при зміні рівня/перезапуску | 0 |

Важливо: не додано жодного RigidBody, raycastу на кадр, нової великої текстури чи physics-симуляції. Уламки й надалі йдуть одним `MultiMeshInstance3D`, горіння обмежене `MAX_ACTIVE_BURNS = 10`, LOW-гвиа залишається меншою за HIGH.

### 2.2. `test/destruction_gallery.gd` (прев'ю / еталон вигляду)

- `Environment.TONE_MAPPER_FILMIC` → **ACES**; glow 0.55 → 0.82; ambient 0.65 → 0.42; тепліший туман.
- Теплий ключовий напрямне світло 1.35 → 1.65 + холодний fill 0.24 + **теплий back-rim** для читаємості силуетів.
- Один повноекранний `CanvasItem`-шейдер: **letterbox + віньєтка + плівкове зерно**. Без `SCREEN_TEXTURE`, тобто без копіювання кадру — практично безкоштовно на Mobile renderer.
- **Тремтіння камери** на детонації й на ударі авіації (затухає за ~0.6 с).
- **Повільний момент 0.34×** тільки на момент детонації в прев'ю (у грі `Engine.time_scale` не змінюється), з очікуванням через `create_timer(..., ignore_time_scale=true)`.
- Контактні тіні + сліди горіння під кожною машиною — один альфа-квад на ціль замість додаткових shadow-map рендерів.
- HUD-фази (`01 · TARGET SET` … `07 · AFTERMATH`) і заголовок, зміщений нижче верхньої шторки.

## 3. Чому FPS на iPhone не просідає

1. **Усе важке запечено/кешовано один раз.** Процедурні текстури 64×64 генеруються один раз і перевикористовуються; ніяких per-frame `Image.set_pixel`, як у старому коді воронки (там був окремий коментар про 1-секундний hitch).
2. **Замість фізики — GPUParticles + MultiMesh.** Уламки рухаються в одному драйвері з інстансованими трансформаціями, не створюючи десятки RigidBody3D.
3. **Новий лінзоподібний фронт тиску зменшує overdraw** порівняно з колишньою великою прозорою сферою — це пряма економія fill-rate, найважливішого ресурсу на iOS.
4. **Бюджетні перемикачі вже є й працюють:** `QualityManager.Level.LOW` зменшує кількість частинок і уламків; `MAX_ACTIVE_BURNS = 10` не дає «засмітити» сцену десятками постійних систем.
5. **Постобробка прев'ю — один quad без зчитування екрана.** ACES-тонмапінг у Godot — це частина того самого env-проходу, без додаткового render target.

Орієнтовна зміна бюджету на один вибух (HIGH): −1 великий прозорий sphere → +1 маленький additive sphere + 1 GPUParticles-емітер; на палаючий об'єкт +1 емітер. Загалом нейтрально/позитивно.

## 5. Що залишити на наступний етап (не робилось у цій ітерації)

1. Замінити примітивні `BoxMesh` уламки на запечені шматки реальної техніки (Blender Cell Fracture → VAT/ànimated mesh), як описано в `Промт для покращення/1.txt`.
2. Воронка `explosion.gd` поки декоративна (декаль, без вирізання ґрунту) — це свідомий бюджетний вибір.
3. Профілювання на реальному iPhone (draw calls, GPU frame time, thermals) — без нього будь-які подальші графічні зміни залишаються вгадуванням.
4. Підключити галерею як «режим перегляду руйнувань» у меню (зараз це виключно test-scene).
